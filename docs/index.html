Why terminals resist sandboxing

A write-up on the Flatpak terminal problem — with a working reference implementation of the escape hatch, packaging Alacritty.

Read the write-up Source

This is primarily an educational project. The question it answers is a real one: why is there no Flatpak of Alacritty, and what would it take? The answer turns out to be architectural rather than a packaging oversight — the same problem Ptyxis solves with a host-spawned agent, and that GNOME Terminal's design cannot solve at all. The manifest here is the reference implementation: something to read, build, and check the claims against.

Unofficial and unendorsed. The Alacritty project has declined official Flatpak support and asked that unofficial packages not be published. This is built independently under Alacritty's Apache-2.0 licence. Report packaging bugs to this repo, never to the Alacritty project. For a supported Flatpak terminal, use Ptyxis.

Why a Flatpak terminal is hard

A sandboxed terminal either runs your shell inside the sandbox — trapping you in the runtime's filesystem instead of your real system — or punches a hole to the host to spawn processes there. Upstream's position is that both outcomes are bad, so terminals fit Flatpak's model poorly on principle.

This build takes the second path, using the mechanism an Alacritty maintainer suggested in passing: override terminal.shell to launch flatpak-spawn --host bash -l. The GPU and UI process stay sandboxed; the shell session runs on the host. Verified by comparing mount namespaces:

processmount namespace
a host shellmnt:[4026531832]
alacritty (sandboxed)mnt:[4026533599]
the spawned bash -lmnt:[4026531832] — matches host

It is the same trick Ptyxis uses in production, via its separately host-spawned ptyxis-agent. The full write-up — including why GNOME Terminal has no Flatpak at all — is in Findings.md.

Configuration

The shell override ships inside the app and is passed by the desktop entry. It imports your own ~/.config/alacritty/alacritty.toml if present — your fonts, colours and keybindings apply, while the shell override stays in force.

Try it

Building it yourself is the honest way to verify any of the above; the manifest is in the repo. If you just want the artifact to poke at, a .flatpak bundle is on Releases, and a signed repo exists if you would rather flatpak update track it:

flatpak install --user ./Alacritty.flatpak
# or
flatpak install --user https://superuser-miguel.github.io/alacritty-flatpak-repo/alacritty.flatpakref

To confirm the host-shell claim on your own machine, launch it and compare readlink /proc/<pid>/ns/mnt for the alacritty process against the bash -l it spawns.
